# UVE parity matrix (Ultimate Video Enhancer 1.17.5 → UVE Player)

Source: `uve.user.js` of UVE 1.17.5 (formerly `legacy-electron/plugins/uve/uve.user.js`; the folder was removed in 1.1.8). Line numbers refer to that file.
Reference values: `tests/reference/uve_reference.json`, generated by running the **original functions** in a
Node vm sandbox (`scripts/uve-reference.mjs`). Test: `tests/unit/tst_uve.cpp` (all 15 conversion functions exact, tolerance 1e-9).

Color space convention: in the browser, UVE works on sRGB-encoded canvas values. The native port works in the mpv hook `MAIN`
(RGB after YUV→RGB, source-encoded, e.g. BT.1886/sRGB). For SDR material this matches the UVE convention; with HDR sources
(PQ/HLG) the controls act on the encoded values before mpv tone-maps – **not equivalent**, see below.

## Known deviations (intentional)
1. **Denoise/CAS:** removed since 1.0.1 (the bilateral filter visibly weakened the sharpness controls).
2. **LUT:** real 3D interpolation instead of the 4×4 matrix approximation → closer to the intent of the `.cube` file, visibly different from UVE GPU mode.
3. **HDR sources:** effects act on PQ/HLG-encoded values before mpv's tone mapping; the result differs from the browser.
4. **HDR warm-up and multi-video throttling** are dropped (only one video).
5. **SVG and GPU chain combined:** in UVE, SVG mode (SL/SR/BL/WL) and GPU mode (grading shader) exclude each other.
   The native port applies both in one chain: unsharp mask (SL/SR) → BL/WL → grading (incl. Teal & Orange) → detail sharpness → LUT profile.
   This way profiles such as `My_Profile.json` (`renderMode: "svg"`, BL 0.7, WL 0.2) take effect with their main controls even when grading values are set.
